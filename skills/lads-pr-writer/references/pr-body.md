# Pull request body template

Use this only when the repository has no pull request template of its own (see step 2 of the skill). Keep every heading and the checklist; replace each `<!-- -->` hint with content, or "n/a" if the section doesn't apply.

```markdown
## 📝 Description

<!-- What changed, why it changed, and the business/technical impact. Max 3-4 sentences. -->

## 🔗 Related Links

<!-- GitHub issue numbers, Notion/Linear/Jira tickets. -->

## 🔍 Technical Changes

<!-- Non-obvious technical changes: schemas, contexts, migrations, API, message processing, integrations.
     High-level if the PR follows an existing pattern; detailed if there are breaking changes, complex migrations, or non-obvious workarounds. -->

## 🧪 How to Test

<!-- Prerequisites, step-by-step instructions, and expected results. -->

## 📌 Additional Notes

<!-- Breaking changes, migration safety, performance, security, compliance, dependencies, monitoring. -->

### Additional requirements

We need to perform these steps for release:

- [ ] None 😊
```
